区块链应用导论讲稿

PPT 讲稿

P1 智能合约与虚拟货币网络的原理与应用探索

尊敬的老师、亲爱的同学们，大家好！我是软件2208班的高洺策 我们今天的汇报主题是——《智能合约与虚拟货币网络的原理与应用探索》。

P2

整个内容将分为六个部分：

首先，我们会简要回顾区块链的起源和研究背景出发 接着，讲解当前主流虚拟货币网络的结构特点，例如比特币和以太坊。

第三部分将进入智能合约的基本概念和作用，然后详细解析其技术架构和执行流程。 在第五部分，我将展示我亲手部署和调用的智能合约 demo，包括与 MetaMask 和 Web 页面联动的实际操作。

最后，是我对智能合约未来发展趋势的简要思考与展望。

P3

在正式介绍智能合约之前，我们先回顾一些区块链的整体背景

P4

区块链最早由中本聪在 2008 年提出，核心特性是去中心化、不可篡改，依靠密码学与共识机制保障安全和透明。 它逐渐催生出 DeFi、NFT 和 Web3 等应用，对现实经济产生了深远影响。

2015 年，以太坊引入了智能合约，使区块链从“记账工具”变成了“可编程平台”，而我们这次实操所使用的 Sepolia，就是以太坊的测试网络之一。

P5

刚才我们简单回顾了区块链的起源，那接下来我们就来聊聊虚拟货币——也就是区块链最典型的应用，它的网络到底是怎么运作的。

P6

虚拟货币网络的核心架构可以从三个方面理解。

首先是分布式账本，它没有中心服务器，每个节点都保存一份完整账本，这使得数据具有不可篡改和全网共识的特点。

第二是节点与矿工。节点是接入网络的计算机，负责转发和验证交易。而矿工或验证者则承担打包新区块的任务，并获得奖励。

最后是共识机制，也就是决定“谁来记账”。常见机制有 PoW 的工作量证明、PoS 的权益证明，还有 DPoS 的投票机制，它们分别适配不同的网络性能和安全需求。

P7

我们可以看到，比特币 是最早的区块链应用，它的核心功能是点对点的货币转账，采用工作量证明机制（PoW），虽然安全性高，但效率较低，每秒只能处理约 7 笔交易，开发生态相对保守。

相比之下，以太坊 是一个功能更强大的平台。它引入了智能合约，使区块链不再只是记账工具，而是可以运行各种去中心化应用。目前以太坊已完成向权益证明（PoS）的过渡，TPS 提升至 15 到 30 左右，并形成了较为活跃的开发生态，支撑了 Web3、NFT 和 DeFi 等大量创新项目。

最后是Solana，作为新兴公链，它最大的特点是高性能和高吞吐，结合了 PoS 与 PoH（历史证明）机制，在理论上支持 2000 笔以上的 TPS，适合运行复杂、实时性高的智能合约应用。不过，它仍在快速发展中，生态尚未完全成熟，也存在一定的中心化争议。

P8

了解了虚拟货币的底层结构之后，我们现在把视角转向它最重要的衍生能力之一——智能合约。

P9

那我们先来回答一个最基本的问题：什么是智能合约？

从字面理解，它是一种“智能的合同”，但本质上它是部署在区块链上的一段可以自动执行的程序代码。一旦合约被触发，它就会在不依赖第三方的情况下，按照既定逻辑执行操作，整个过程不需要人为干预。

根据密码学家 Nick Szabo 在 1994 年的定义，智能合约是“一个自动执行合同条款的计算机化交易协议”（引用如图所示）。这句话的核心含义是：它不仅仅是合同的数字化，而是把合约“写成代码”直接运行在链上。

智能合约具有三大核心特性：

首先是自动化执行，它的运行基于代码逻辑，不依赖于人工或机构介入；

第二是无需信任，因为区块链的共识机制和加密验证，确保合约运行结果可信；

第三是公开透明，所有代码、参数和执行过程都可在链上查看，增强了可审计性和防篡改性。

也正因为这些特性，智能合约成为了去中心化金融、NFT、DAO 等 Web3 应用的技术基础。

P10

第一类是 DeFi 合约，也就是去中心化金融，它可以实现借贷、交易等金融服务

第二类是 NFT 合约，主要用于定义和转移数字资产的所有权，比如我们熟知的一些游戏资产交易平台。

第三类是 DAO 治理合约，让社区用户通过投票来共同决策并自动执行

最后是 供应链合约，用于追踪商品流通和自动结算

P11

在了解了什么是智能合约以及它有哪些典型应用之后，接下来我们进一步看看，智能合约是如何被构建、部署和执行的。

P12

目前主流的智能合约开发语言中，Solidity 是使用最广泛的，它是专门为以太坊设计的，几乎所有基于以太坊的合约都用它编写。

Vyper 是一个更注重安全性的语言，语法风格类似 Python，但功能相对受限，适合对合约安全性要求高的场景。

除此之外，还有一些合约是用Rust、Go、C++ 等语言开发的，适用于特定链或私有链平台。

P13

第一步是编译：我们通常使用 Solidity 编写合约源码，编译后会生成字节码（bytecode）和 ABI 接口说明，这些内容是部署和调用合约的基础。

第二步是部署：合约通过一笔特殊的交易被发送到以太坊网络中，一旦部署成功，它就会拥有一个唯一的合约地址，供后续调用。

第三步是调用：我们调用合约里的函数，其实本质上是再次发起一笔交易，这可能会改变链上状态，或者只是读取数据。

接下来是确认：矿工或验证者会将这笔交易打包进新区块，一旦被确认，就算“写进了账本”。

最后是上链：交易和执行结果被正式写入区块链，不可篡改，形成了链上的合约状态变更记录。

这个流程也体现了智能合约“公开透明、自动执行、上链即不可逆”的技术特性。

P14

前面我们已经讲清楚了智能合约的概念、结构和执行流程，那接下来就进入本次展示的重点部分——实操演示。

P15 ~ 18

你的问题非常好！你已经成功部署了智能合约（例如 Storage 合约），然后在 Web 页面中通过按钮触发 storeValue() 和 viewValue() 函数进行交互，这时会通过 MetaMask 来发起交易或读取数据。

那么问题是：

❓为什么调用智能合约的“存值”和“查值”操作要通过 MetaMask？MetaMask 起到了什么作用？

🧠 MetaMask 的角色可以理解为：你与区块链之间的“钱包+签名器+交易网关”

🔍 一、MetaMask 是什么？

MetaMask 是一个浏览器插件钱包，作用包括：

功能 说明
✅ 钱包 用于管理用户账户、生成地址、保管私钥（例如你的 0xabc... 钱包地址）
✅ 签名器 当你想“发起交易”时，它会请求你的授权并使用私钥签名
✅ 区块链网关 它会把签名好的交易广播到以太坊网络，如 Sepolia

⚙️ 二、为什么存值要用 MetaMask？

function store(uint num) public {
    money = num;
}

这段代码会修改区块链上的状态，所以：

  • 这是一次“交易”（Transaction）
  • 必须由用户签名（防止恶意伪造）
  • 需要支付 Gas 费
  • 所以： ✔️ 必须通过 MetaMask 获取用户签名
    ✔️ 通过钱包广播这笔交易给区块链

➡️ 你的代码中 contract.methods.store(value).send({ from: accounts[0] }) 正是调用 MetaMask 发起交易。

🔎 三、那为什么 查值（view_money） 不需要签名？

function view_money() public view returns (uint) {
    return money;
}
  • 这是一个 view 函数，不修改区块链，只读取链上已有数据
  • 这类函数可以直接用 call() 调用，不需要 Gas、签名或广播
  • 所以可以不用 MetaMask 授权，但仍需要 web3.js 从链上读数据

你的代码中：

const value = await contract.methods.view_money().call();

这不会弹出 MetaMask，而是直接读取链上数据。

🔗 四、总结：MetaMask 的作用可以类比为你的“银行APP”

操作 类比 是否需要 MetaMask
存值 store() 给账户转账（要钱、要签名） ✅ 需要签名和Gas
查值 view_money() 查询账户余额 ❌ 不需要签名

💡 你网页的工作流程是这样的：

  1. 用户点击“连接钱包”按钮：→ MetaMask 弹窗连接 → 获取钱包地址
  2. 用户输入一个值并点击“存储”：→ send() → MetaMask 弹窗请求签名 → 发送交易 → 上链
  3. 用户点击“读取”：→ call() → 直接读取合约值 → 显示结果

P19

通过前面的内容和演示，我们已经完整了解了智能合约的技术原理与实际操作。 最后，我想对整个汇报做一个简要总结，并分享一些我对智能合约未来发展的思考。

P20

最后，我想对智能合约未来的应用前景做一个简要展望。

首先，在应用层面，智能合约很可能成为 Web3 架构的核心组成部分，支撑数字身份、链上治理以及知识产权保护等场景的可信执行。也就是说，它将不再局限于金融，而是深入到我们日常的社会基础设施中。

同时，AI 的发展也为智能合约带来了新的可能。例如我们可以用大模型自动生成合约草稿，或者通过 AI 决策机制触发链上执行，这种“AI + Chain” 联动机制将大大提升自动化和智能性。

当然，未来的发展也面临一些挑战。比如合约漏洞、权限滥用仍然是风险源头。我们还需要加强形式化验证、安全审计，以及推动“可信执行+法律约束”的融合，让智能合约不仅可运行，也能被社会所接纳。

P21

智能合约不只是代码，更是我们迈向可信数字社会的重要基石。 谢谢大家的聆听

✅ 一、PoW（Proof of Work，工作量证明）

📌 原理

  • 由 比特币 首创的共识机制。
  • 每个节点（矿工）必须通过解一个复杂的数学难题（哈希计算）来获得“记账权”。
  • 谁先解出题，谁就能将新区块加入区块链，并获得奖励（如 BTC）。

🧠 举个例子

就像在全班抢答题目，谁最先举手答对，谁就能上黑板写答案，并记进班级记录册。

✅ 优点

  • 安全性高，攻击成本巨大。
  • 全网计算力越大，越难被攻击（如 51% 攻击）。

❌ 缺点

  • 能耗高（“挖矿”需要大量电力）。
  • 效率低，TPS（每秒交易数）较低，例如比特币只有 7。

🌍 应用

  • Bitcoin、Ethereum（旧版）等

✅ 二、PoS（Proof of Stake，权益证明）

📌 原理

  • 不再比算力，而是根据你持有的代币数量和“持币时间”来选出下一个区块的记账者。
  • 可以理解为“谁押得多，谁更有机会记账”。

🧠 举个例子

你像是在买房摇号，但押的定金越多、参与时间越久，中签概率就越高。

✅ 优点

  • 节能环保，不再靠高能耗挖矿。
  • 出块速度更快、交易费用更低。
  • 更容易实现去中心化治理（代币投票机制）。

❌ 缺点

  • 有“富者越富”的倾向（持币多的人更容易掌控共识）
  • 攻击者可能通过持有大量币来影响网络安全（但有“惩罚机制”来防止）

🌍 应用

  • Ethereum（合并后转为 PoS）
  • BNB Chain、Polygon、Cardano

✅ 三、PoH（Proof of History，历史证明）——Solana 独有机制

📌 原理

  • PoH 不是独立的共识机制，而是对 PoS 的时间优化补充机制。
  • 通过一个加密时钟记录事件和交易顺序，避免网络中节点“等谁先发块”的问题。
  • 所有交易先写时间戳 → 共识再跟进 → 效率极高

🧠 举个例子

就像你看比赛录像，有时间轴就知道每个动作先后，无需争吵“谁先干的”。

✅ 优点

  • 极大提升 TPS（Solana 可达 2000+）
  • 适合高并发、低延迟的金融、游戏、链游等场景

❌ 缺点

  • 技术复杂，节点门槛较高
  • 目前生态尚未完全成熟
  • 易被质疑中心化程度偏高

🌍 应用

  • Solana（结合 PoS + PoH）

📊 总结对比表

特性/机制 PoW（工作量） PoS（权益） PoH（历史）
出块权决定方式 算力强者胜 押币多者优先 时间戳排序 + PoS
能耗 高 低 很低
TPS 较低 中等 很高
安全性 非常高 高 高，但机制复杂
代表项目 Bitcoin Ethereum、Cardano Solana

✅ 应对问答小技巧

如果老师问：“你觉得哪种机制更好？”

回答建议：“没有绝对好坏，要看应用场景。PoW安全但慢，适合价值存储；PoS能效高适合构建生态；而PoH则适合需要高性能、低延迟的实时系统。”
